# AGENTS.md — rules for humans and AI agents working on this repo

Multi-tenant PWA for barbershop online booking. One shared frontend build,
one Supabase project, every tenant isolated by `tenant_id`.

## Non-negotiable invariants
1. **No tenant names in `src/`.** Branding, texts, services, prices, rules come
   from `tenants/<slug>/business.json` → DB. `npm run lint:tenants` enforces it.
2. **DB is the runtime source of truth.** Clients never send price, duration,
   tenant_id, or a barber chosen after availability checks; SQL reads them.
3. **All writes go through SQL RPCs** (`supabase/migrations/*`). anon has no
   table grants; authenticated only membership-scoped SELECT. Every
   `SECURITY DEFINER` function pins `search_path = ''`.
4. **Bookings and blocks share `resource_occupancies`** with a PostgreSQL
   `EXCLUDE` constraint. Never check-then-insert without it.
5. **Historical snapshots on bookings are immutable** (trigger-enforced).
6. **Service-role key and LLM key never reach the browser.** Only `VITE_*`
   variables are public.
7. **Private (owner) data is never cached by the service worker** and the
   TanStack Query cache is cleared on logout.
8. **Do not call mocked responses "integration".** Local tests use a local
   PostgreSQL and a local HTTP emulator of the Supabase surface
   (`tools/local-stack`); real Supabase checks are listed in ACCEPTANCE.md.

## Layout
- `supabase/migrations` — schema, RLS, RPCs (ordered). `supabase/seed.sql` is generated.
- `supabase/functions` — Edge Functions (`ai-chat`, `notify-worker`); shared pure TS in `_shared`.
- `supabase/tests` — SQL tests (`scripts/db/test-sql.sh`) incl. real concurrency.
- `tenants/<slug>/business.json` + images — pipeline input. `tenants/_template` for new shops.
- `scripts/tenant` — `tenant:new|validate|publish|verify`; `scripts/build-shells.ts` — per-tenant PWA shells.
- `src/` — React app (`/s/:slug/` client, `/s/:slug/owner/` cabinet).
- `tools/local-stack` — dev/test emulator of PostgREST RPC + Auth + Storage + Functions over local Postgres.

## UI stack rules
- Astryx (`@astryxdesign/core`) is the component system; Theme provider gets a
  runtime `defineTheme` with the tenant accent (dark mode).
- shadcn/ui is used only for the **Base UI** Drawer branch (`src/components/ui/drawer.tsx`).
  Do not add Vaul or Vaul props. shadcn classes must use Astryx-backed utilities.
- CSS layer order lives only in `src/styles/globals.css`.
- Run `npx astryx component <Name>` before using unfamiliar props.
- Every network screen handles loading / error / empty / success.

## Commands
- `npm run db:test` — SQL + concurrency tests on local Postgres.
- `npm run typecheck`, `npm run test`, `npm run build`, `npm run e2e`.
- `npm run tenant:validate -- <slug>` before any publish.
